# GitHub AI PR 审查与合并能力契约

## 目标

在代码版图控制台内完成追踪仓库的 PR 预览、Diff/源码上下文检查、Codex SDK 审查、合并计划生成与人工确认合并，不要求管理者跳转到 GitHub。

## 能力分层

| 能力 | 判断深度 | 控制等级 | 说明 |
| --- | --- | --- | --- |
| PR 队列、Diff、源码与检查读取 | D1-D2 | C1-C2 | 只读 GitHub 事实，限制仓库、文件数和字节数 |
| AI 合并建议 | D2-D3 | C2 | 模型可识别风险、比较 Diff 与允许读取的源码、给出结构化建议 |
| 生成合并计划 | D4 | C3 | 确定性代码重新校验 head SHA、CI、评审、规模和敏感路径 |
| 执行合并 | D5 | C3 | 必须使用短时一次性令牌，执行前再次读取 GitHub 并校验全部门禁 |

## 模型可以决定什么

- 解释变更意图、潜在缺陷、兼容性和安全风险。
- 在受限源码上下文中比较变更前后实现，并引用文件级证据。
- 输出 `merge`、`needs_changes`、`manual_review` 或 `insufficient_evidence` 建议。

模型输出不包含隐藏思维过程，只展示结论、发现、证据、未知项和置信度。

## PR 级审查边界

- AI 默认只评价当前 PR 的变更级别风险，不把“完整项目”的交付要求套到尚在迭代的 PR 上。
- 缺少全量文档、CI、批准评审、发布材料或超出默认规模，只作为未知项/外部合并门禁展示，不单独构成代码风险结论。
- 只有当前补丁存在可定位缺陷、回归、安全问题，或缺少评估当前风险所必需的局部证据时，才会给出需要修改或人工复核。
- `merge` 仅表示“当前补丁未发现代码级阻断”，不等于项目完整，也不等于已经满足合并门禁。

## 确定性代码必须执行什么

- 只允许 `owner/repository` 格式的仓库和正整数 PR 编号。
- PR 必须仍为 OPEN、非草稿、可合并，并与审查时的 head SHA 完全一致。
- 必须满足仓库策略要求的 CI、批准评审、变更规模及人工审查路径规则。
- AI 结论必须为 `merge` 且置信度达到仓库阈值；模型不能绕过任一门禁。
- 合并计划绑定仓库、PR、head SHA、合并方式和门禁摘要，十分钟后过期且只能使用一次。
- 执行合并后校验 GitHub 返回的 `merged=true`，失败则保持未完成状态。

## 默认策略

- 自动执行合并：关闭。
- 合并方式：squash。
- 要求 CI：开启；没有可验证检查时阻止合并。
- 要求至少一个批准评审：开启。
- 最大变更：40 个文件、1500 行。
- `.github/workflows/`、`deploy/`、`infra/`、`migrations/`、`auth/`、`security/` 等路径只能人工深度复核。
- 源码读取：最多 12 个文本文件、合计 80 KB；二进制、锁文件、生成物和超限内容不读取。

## 失败与撤回

- GitHub 读取、Codex SDK 或结构化输出失败时，AI 结论失败关闭；CI/评审等合并门禁证据缺失只阻止合并计划，不把它自动升级为当前代码的 `needs_changes`。
- 刷新 PR 或再次运行 AI 审查可替换旧结论；head SHA 改变会使旧审查和旧令牌立即失效。
- 合并是不可逆的仓库写操作，因此控制台不会提供绕过确认的隐藏路径。
